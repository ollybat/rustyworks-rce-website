The gate

Nothing runs until setup is finished

Two things have to exist first: at least one staff role saved, and one Rust server linked and tested over RCON. Until then every command answers with that checklist instead of doing anything at all. /setup is the one exception, because it is how you get there, and /ping and /help still work: they only report.

The roles you save are the staff roles

  • Six slots: Owner, Co-Owner, Head Admin, Admin, Moderator and Linked.
  • Anyone holding one of those roles may run staff commands.
  • Administrator, Manage Server and the server owner always count, so nothing can lock you out.
  • Put into practice on every command, button, menu and modal — not just hidden from the command list.

Why a link is not taken on trust

  • A player asking to link is making a claim, not offering proof.
  • The bot records it as waiting, never as linked.
  • Staff confirm it with /user forcelink, or the server verifies it in game.
  • Looking somebody up prints ids as text, so it cannot notify or ping them.

Said plainly

What Spinback will not do

A command that quietly invents a plugin command name, a price or a kit list is worse than one that refuses. These are the limits, on purpose.

It refuses rather than guesses

  • No invented kit plugin commands: give it your own, or nothing is sent.
  • No invented emote names, prices, rarities or dates.
  • No made-up server numbers: every figure on /ping is measured at that moment.
  • No reading your Rust server beyond the four allowed RCON questions.

And what that means for you

  • If a panel says a save stayed in the bot's memory, it could not reach its own storage — it tells you that plainly.
  • If RCON times out, you get the reason and the usual causes, not a green tick.
  • If a link request is unproven, it stays waiting until a person or the server confirms it.
  • If a command cannot do something, it says which step is missing.
