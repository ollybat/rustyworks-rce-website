/ping — live health check

Everyone No options

One embed, and every line in it is measured at the moment you run it: the gateway heartbeat, how long the bot has been up, its Node version, resident and heap memory, the server it is in with member and role counts, how many commands it registered, and a live request to this website with the round-trip time.

What each field means

Gateway is the heartbeat between the bot and Discord, not your ping. Memory is the bot process, in megabytes. The website line is a real request made seconds before you read it, and if the site is unreachable it shows how long it waited and why instead of a green tick. The settings line tells you whether saves can reach this site at all; if it says not configured, every other panel will tell you the same.

/setup — configure the bot

Staff roles, Administrator or owner Needs RCON details

Your server, wired up in three steps. The Rust connection is tested with a real serverinfo before anything is saved, so a wrong port or password never lands in your settings, and the server's own reply is shown back to you.

SubcommandWhat it doesNotes

Step 3 your Rust server. Role-id values that are not ids are counted and reported, never stored silently.

/setup refresh Opens a fresh RCON connection to a saved server and reports exactly what it answers. Useful when the game server restarted and a cached connection went stale.

The gate

Nothing runs until setup is finished

Two things have to exist first: at least one staff role saved, and one Rust server linked and tested over RCON. Until then every command answers with that checklist instead of doing anything at all. /setup is the one exception, because it is how you get there. /ping and /help still work: they only report.

All of it happens in Discord, in the panel behind each command: step 1 roles, step 2 log channels, step 3 your Rust server. This website is here to help you read and use the bot — it never configures your server, and it asks for no account and no password.

The roles you save are the staff roles

  • Step 1 saves Owner, Co-Owner, Head Admin, Admin, Moderator and the linked role.
  • Those roles, plus Administrator, Manage Server and the server owner, are the people who may run anything that configures or edits.
  • Until one is saved, only Administrator, Manage Server and the owner can run anything, so a server cannot lock itself out.
  • The bot enforces this on every use, not just in the command list, so a role removed in Discord stops working immediately.

Why a link is not taken on trust

  • A request from the link panel is a request, and it says clearly that it is waiting.
  • Staff confirm it with /user forcelink, or your server's own in-game verification does it.
  • One gamertag belongs to one Discord account. The clash is reported with the account already holding it.
  • Unconfirmed requests never drive kits, auth groups or the roster.
How setup goes

Three steps, in this order

Each one is a button on the setup panel. You can stop after any step and come back later; /setup status remembers where you got to.

  1. Roles. Save the six slots so every staff-only feature knows who is who.
  2. Logging channels. Choose the channel for each of the fifteen log types you actually want. A type with no channel is simply switched off.
  3. Your Rust server. Name, address, RCON port and password. The bot connects, sends serverinfo, shows you the answer, and only then saves.

What the bot will not guess

  • Kit plugin command names, and the emote names themselves.
  • Anything your Rust server has not told it: kit lists, rosters, cooldowns.
  • Skin prices, rarities or release dates it cannot read from the store.
  • Numbers. If something cannot be measured, the panel says so instead of showing a placeholder.

Before you start

  • Permissions: staff commands are for the roles saved in step 1 of setup. Administrator, Manage Server and the server owner always count, so nothing can lock you out.
  • RCON: the port and password from server.cfg, with rcon.web set to 0. Addresses on the private internet are refused.
  • Saving: if a panel says a save stayed in the bot's memory, the bot could not reach its own storage — it tells you that plainly rather than pretending it stuck.
