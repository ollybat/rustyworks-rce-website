Set-up guide

Get started

The whole of Spinback RCE, wired up in about ten minutes, and all of it inside Discord. Every step is a button you press: nothing is created until you press Create, no step depends on an earlier one finishing, and you can stop at any point without leaving anything half-done.

Before you start

Three things, and only the first one takes any finding.

Permission to manage the server

Staff commands answer to Administrator, Manage Server, the server owner, and the roles you save as staff roles. If you can create roles and channels, you can finish this in one sitting.

Your RCON details

Host, RCON port and password, the three lines at the top of your server.cfg. The bot tests them before it saves anything, so a wrong port or password never lands in your settings.

The bot, in your server

Invites are closed: the bot is added by hand through the support server. Once it is in, there is no account on this website and nothing to sign up for.

The steps

Run them in this order the first time. Each one is a single Discord command that opens a panel.

  1. 1

    Get the bot in

    Invites are closed, so the bot is added by hand through the support server. Once it is in your server its commands register on start-up: if the list looks empty, give it a moment and reopen Discord.

  2. 2

    Run /setup run

    /setup run

    The guided panel: staff roles, then log channels, then your Rust server last. Each step is optional and independent, and every item reports back with a reason if it fails.

  3. 3

    Create the staff roles

    /setup roles

    The roles it creates are saved as your staff roles. From then on, only those roles, Administrator and the server owner can run staff commands: nobody else, including the bot's own linked role.

  4. 4

    Make the log channels

    /setup channels

    The channels it makes are private to the saved staff roles by default, so members cannot read them. Pick the log types you want and the channel for each; clearing a channel switches that type off.

  5. 5

    Connect the Rust server

    /setup server

    Host, RCON port and password. The connection is tested live before anything is saved, and the panel names the reason when it fails rather than guessing. The RCON port is the one from server.cfg, not the port players join on.

  6. 6

    Your first kit

    /kits commands

    Save the list command your kit plugin uses and the give command you already type, then /kits grab reads the real kit names straight from your server and /kits give sends your own give command with the player and kit filled in. The bot never invents a kit name.

  7. 7

    Check it

    /setup doctor/ping

    /setup doctor names anything that is still missing and what to press next. /ping measures the bot, the gateway and this website at the moment you run it.

What the bot will not do

It will not invent anything

  • No guessed kit names, prices or player data: where the bot cannot know something, the answer says so.
  • No saving an RCON address it could not reach during the test.
  • No staff command answering to anyone outside the roles you saved, Administrator and the owner.

This site will not change your server

  • No login, no account, no server settings here: server setup lives in Discord, where the permissions already are.
  • The site reads the bot's own status and remembers your display choices in this browser only.
  • Nothing on these pages is typed by hand: the command list is drawn from what the bot actually registers.

Not connected yet

Emote binds, respawn kits and the log types that come from in-game events are saved and shown, but they only run in game once a Rust plugin sends those events to the bot. That feed is not connected yet, and the bot says so in the panel rather than pretending otherwise.

If something is not working

Six things people actually run into, what each one means, and where to look next. Nothing here guesses: where the bot cannot know an answer it says so, and so does this page.

"The website is not answering" in /ping

  • That line is a live request from the bot to this site, with a 2.5 second limit on it.
  • This site answers in tens of milliseconds, and in under two seconds even on the first request from a place it has never been asked before, so a timeout means that one check was slow, not that the site is down.
  • The status page shows the same measurement, so you can compare it yourself. If it keeps happening, that is worth reporting: it is not something you did.

The settings store is "not kept"

  • The bot has nowhere durable to put what you save: it needs the settings token set on its own host, with the same value here, or a disk attached to it.
  • Until that is set, saved servers, staff role slots and kits are forgotten the next time the bot restarts or is redeployed.
  • That is a setting on the bot’s host, not something this website can change. The servers page says so plainly when it is the case.

No servers are listed here

  • Two honest reasons, and the page tells you which: the bot is up and has no Rust server saved yet, or it had one and forgot it because of the point above.
  • The step that adds one is /setup server: it tests the address before saving, so a wrong port or password never lands in your settings.
  • This site never shows an RCON address or a password, and it never guesses a server’s state: anything the bot has not reported says so.

A panel asks for RCON

  • Kits and emblems reach your Rust server, so the connection has to exist first: /setup server is that step.
  • A private address (192.168.x.x, 10.x.x.x, 127.0.0.1) cannot be reached from a host on the internet, so it is named as private instead of failing silently.

A button says this has not been set up yet

  • /setup run walks the whole thing: roles, log channels, the Rust server, then kits.
  • Nothing is created until you press Create, no step needs an earlier one to be finished, and you can stop halfway without leaving anything broken.

The bot itself shows as offline

  • This site reads the bot’s own public status, so "not answering" means the bot process could not be reached, which is a restart on its host rather than anything on these pages.
  • There is no invite link on this site by request, and nothing here has a login: every change to your server happens in Discord, where the permissions already are.
