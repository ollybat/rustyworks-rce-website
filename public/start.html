Set-up guide

Get started

The whole of Spinback RCE, wired up in about ten minutes, and all of it inside Discord. Every step is a button you press: nothing is created until you press Create, no step depends on an earlier one finishing, and you can stop at any point without leaving anything half-done.

Add to Discord See every command Live status

Before you start

Three things, and only the first one takes any finding.

Permission to manage the server

Staff commands answer to Administrator, Manage Server, the server owner, and the roles you save as staff roles. If you can create roles and channels, you can finish this in one sitting.

Your RCON details

Host, RCON port and password, the three lines at the top of your server.cfg. The bot tests them before it saves anything, so a wrong port or password never lands in your settings.

The bot, invited

One press on Add to Discord, then pick your server and approve. There is no account on this website and nothing to sign up for.

The steps

Run them in this order the first time. Each one is a single Discord command that opens a panel.

  1. 1

    Invite the bot

    Press Add to Discord and approve it for your server. The bot registers its commands when it starts; if the list looks empty, give it a moment and reopen Discord.

  2. 2

    Run /setup run

    /setup run

    The guided panel: staff roles, then log channels, then your Rust server last. Each step is optional and independent, and every item reports back with a reason if it fails.

  3. 3

    Create the staff roles

    /setup roles

    The roles it creates are saved as your staff roles. From then on, only those roles, Administrator and the server owner can run staff commands: nobody else, including the bot's own linked role.

  4. 4

    Make the log channels

    /setup channels

    The channels it makes are private to the saved staff roles by default, so members cannot read them. Pick the log types you want and the channel for each; clearing a channel switches that type off.

  5. 5

    Connect the Rust server

    /setup server

    Host, RCON port and password. The connection is tested live before anything is saved, and the panel names the reason when it fails rather than guessing. The RCON port is the one from server.cfg, not the port players join on.

  6. 6

    Your first kit

    /kits commands

    Save the list command your kit plugin uses and the give command you already type, then /kits grab reads the real kit names straight from your server and /kits give sends your own give command with the player and kit filled in. The bot never invents a kit name.

  7. 7

    Check it

    /setup doctor/ping

    /setup doctor names anything that is still missing and what to press next. /ping measures the bot, the gateway and this website at the moment you run it.

What the bot will not do

It will not invent anything

  • No guessed kit names, prices or player data: where the bot cannot know something, the answer says so.
  • No saving an RCON address it could not reach during the test.
  • No staff command answering to anyone outside the roles you saved, Administrator and the owner.

This site will not change your server

  • No login, no account, no server settings here: server setup lives in Discord, where the permissions already are.
  • The site reads the bot's own status and remembers your display choices in this browser only.
  • Nothing on these pages is typed by hand: the command list is drawn from what the bot actually registers.

Not connected yet

Emote binds, respawn kits and the log types that come from in-game events are saved and shown, but they only run in game once a Rust plugin sends those events to the bot. That feed is not connected yet, and the bot says so in the panel rather than pretending otherwise.
