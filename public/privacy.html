Privacy, plainly

What we store

Spinback is a Discord bot for Rust Console Edition servers, and this website is a helper that reads what the bot publishes. This page lists what is kept, where it lives, what is never shown, and the exact commands that remove it. It is written from the bot's and the site's own code rather than from good intentions, and it names the one thing here that is genuinely sensitive: your server's RCON password, which has to be stored for the bot to connect at all.

none accounts on this site none analytics or tracking 1 thing in your browser: the theme you picked owner only cookies, while signing in

On this website

  • The only thing kept in your browser is your theme choice. It is one local storage key (spinback-theme), plus a one-time flag left behind when that key was renamed. Clear site data and both go.
  • No cookies for visitors. The only cookie this site sets is a signed session cookie, marked HttpOnly, SameSite=Lax and Secure, and only while the bot's owner signs in to the owner tools. It expires by itself.
  • No analytics, no advertising, no tracking pixels, no social embeds, no third-party scripts. Nothing here follows you to another page.
  • One third-party request: the fonts come from Google's font service (fonts.googleapis.com for the stylesheet, fonts.gstatic.com for the files), so Google sees the request your browser makes, exactly as it would on any site using it. Everything else is served from this domain.
  • Outbound links are just links. The Discord support server and two community server sites are ordinary anchors: nothing loads from them until you click.
  • The host sees requests, like any web host. That is a web server log, not a profile, and it is not used to build one.
  • Uptime samples contain no visitor data. The Status page charts the bot's own uptime and guild count; that history is about the bot, not about you.

What the bot keeps

  • Your saved configuration: staff role ids with their names, log channel ids, the Rust servers you add, kits, installs, and the Discord accounts you link.
  • Your Rust servers: a name, an address, an RCON port and an RCON password. The password is the sensitive one - it is stored because the bot has to connect with it.
  • Discord ids: the server, role, channel and user ids needed to act on your server. That is the minimum, and it is all of it.
  • One gateway intent only - Guilds. The bot never asks Discord for the message content intent, so it cannot read ordinary messages even if it wanted to. Log channels receive the bot's own notices.
  • Where it lives depends on how the bot was set up, and the bot tells you which: run /setup status or /ping and read the settings line. It reports whether settings are held on this website, in a Postgres database, on the bot's own disk, or in memory only - and memory only means they are lost on the next restart.

What is never shown

  • RCON passwords. No page, no log and no Discord message prints one. Anything running in a browser is told only whether a password is set, never its value; the full copy is handed to the bot alone, against a shared token.
  • The shared settings token, which is what lets the bot read and write its own settings.
  • The owner's Discord client secret and session secret, used for the owner's sign-in and nothing else.
  • Nothing is sold, shared, or used to train anything. Your settings go nowhere except the store that the settings line names, and the pages you can already see.

How to remove it

  • /setup export first - it prints everything saved for your server, so you can keep a copy before changing anything.
  • /setup reset clears the saved configuration for your server. It asks you to type RESET in capitals, so it cannot happen by accident.
  • /setup edit replaces a saved server's address, RCON port or password.
  • /setup roles and /setup channels unset a slot: choose none for it and the saved id goes.
  • Anything else, including a linked account, is a request in the Discord support server. There is no self-service command for that yet, and this page will not pretend there is.

What this site is not

It has no accounts for visitors, no dashboard, no way to change a server from a browser, and no require-you-to-sign-in step. It reads the bot's own public status and repeats it, and nothing it shows can alter a server. The only signed-in part of it belongs to the bot's owner. The site and the bot are run by the same team, and this page is kept in step with both: if the bot ever changes what it stores, this page changes with it.
